RECLAIM — Implementation Plan (Founder's Code 2026)
Read this whole ﬁle before writing any code. It is the single source of truth for the Reclaim prototype. It is written so that
any developer or AI coding agent can pick up the project at any point, see what is done (Section 18 task board), and
continue.
Event: Founder's Code 2026, 24-hour hackathon, SMIT Chennai, 14–15 Oct 2026. Domain: Cybersecurity & Digital Safety
(example category: "fraud-reporting assistance"). Owner: Shriram (tech lead). One business-track teammate handles
pitch/market.
0. TL;DR for an AI agent picking this up
1. Product: Reclaim — a mobile-ﬁrst web app that walks a UPI/bank-fraud victim through the three oﬃcial reports (1930 call →
cybercrime.gov.in complaint → written bank report), generates every text they need, and tracks the RBI 5-day compensation
window and the bank's 45-day resolution deadline. A bank dashboard shows incoming cases live.
2. Stack: React + Vite + TypeScript + Tailwind (frontend), FastAPI + SQLite (backend), Gemini Flash (free tier) for screenshot
extraction + scam tagging, deterministic fallbacks.
3. The demo must never fail. Every AI call has a cached/demo fallback (Section 9).
4. Time is controlled by a demo clock (DEMO_NOW), because the RBI rule only applies to transactions on/after 1 Jan 2027 and
the event is in Oct 2026 (Section 7.1).
5. Build order = Section 17 timeline. Current status = Section 18 task board. Update it as you go.
6. Never use real personal/ﬁnancial data. Only the fake samples in samples/.
1. The story (what the demo must make the jury feel)
Ravi, 34, Chennai, gets a call: "Your KYC has expired, your account will be blocked." He taps the link, enters his UPI PIN. ₹18,000
is gone (Google Pay → kyc.update@ybl, 12 Jan 2027, 7:42 PM).
Without Reclaim: he panics, doesn't know about 1930, can't ﬁnd the UTR, never writes to his bank. Day 6 he ﬁles a messy
complaint. Money gone. He also misses RBI compensation because compensation needs reports to both 1930/NCRP and the
bank within 5 calendar days.
With Reclaim: his bank's SMS has a Reclaim link. In ~1 hour he has ﬁled all three reports correctly. Reclaim shows
"Compensation-eligible: ₹15,300" (85% of ₹18,000). His bank's fraud team sees his complete case appear on their dashboard
instantly.
Closing line of the pitch: "With Reclaim, Ravi gets ₹15,300 back. Without it, ₹0."

7. Eligibility engine (backend/app/eligibility.py)
7.1 Demo clock
config.DEMO_NOW (ISO string, optional). If set, clock.now() returns DEMO_NOW + (real_now − server_start_time)
so the countdown still ticks.
Default demo value: 2027-01-12T20:01:00+05:30 (19 minutes after Ravi's fraud).
Stage page has controls to jump time: +1 day, Jump to day 4 23h, Jump to day 30, Reset → POST
/api/demo/clock (only when DEMO_MODE=true).
7.2 Rules (constants in one place)
RULE_EFFECTIVE_FROM = date(2027, 1, 1)      # transactions on/after
COMP_MAX_LOSS       = 50_000                # ₹, loss cap for scheme
COMP_RATE           = 0.85
COMP_CAP            = 25_000                # ₹
REPORT_WINDOW_DAYS  = 5                     # calendar days, both bank and NCRP/1930
BANK_RESOLVE_DAYS   = 45                    # domestic
7.3 Function contract
def evaluate(fraud_at: datetime, total_loss: int, prior_compensation: bool,
             ack_1930: str|None, ack_portal: str|None, bank_reported_at: datetime|None,
             now: datetime) -> Eligibility
Eligibility ﬁelds: status (one of below), max_compensation (int ₹), deadline_at (fraud_at + 5 days), seconds_left
(≥0), bank_resolve_by (bank_reported_at or fraud_at + 45 d), message_key (i18n key), reasons (list of strings).
Status logic (ﬁrst match wins):
1. fraud_at.date() < RULE_EFFECTIVE_FROM → NOT_APPLICABLE_DATE
2. prior_compensation → NOT_APPLICABLE_PRIOR
3. total_loss > COMP_MAX_LOSS → NOT_APPLICABLE_AMOUNT
4. now > deadline_at and not both reported before deadline → WINDOW_MISSED
5. NCRP reported (ack_1930 or ack_portal) and bank reported, both before deadline → ELIGIBLE_COMPLETE
6. else → ELIGIBLE_PENDING
max_compensation = min(round(COMP_RATE * total_loss), COMP_CAP) for statuses 5–6, else 0. Ravi: min(15,300,
25,000) = 15,300.
Note in UI: "Estimate. Your bank decides ﬁnal eligibility." (Reclaim never judges negligence.)

2. Gemini (timeout 12 s): image + prompt below, response_mime_type="application/json" with schema. On success →

3. Fallback: return empty ﬁelds with source: "manual" and a friendly message "We couldn't read it — please type the
details." (Optional: Tesseract + regex.)
9.2 Gemini prompt (extraction + classiﬁcation in one call)
Model: a current free-tier Gemini Flash model (put the exact model ID from Google AI Studio in GEMINI_MODEL; do not hard-
code). SDK: google-genai.
You read Indian payment screenshots and bank SMS messages.
Return ONLY JSON matching the schema. Use null when a value is not visible. Never guess digits.
Fields:
- amount_inr: integer rupees debited (no symbols, no paise)
- utr: the UPI transaction ID / UTR / reference number exactly as shown (digits only if UPI)
- txn_datetime: ISO 8601 with +05:30 if date and time are visible
- payer_bank: the payer's bank name if visible
- payment_app: Google Pay | PhonePe | Paytm | BHIM | Bank app | SMS | Other
- method: UPI | Card | NetBanking | Other
- payee_id: the receiver UPI ID, account, or name exactly as shown
- field_confidence: object with a 0..1 confidence for each field above
Also classify the user's description into one scam_type from:
fake_kyc, job_task, investment, digital_arrest, fake_customer_care, sextortion, loan_app, other
and give scam_confidence 0..1 and a one-sentence incident_summary in plain English.
User description: """{description}"""
9.3 Validation/normalisation (extract/validate.py)
UTR: keep digits; UPI UTR should be 12 digits → else conﬁdence ≤ 0.5.
Amount: int > 0; if > 10,00,000 → conﬁdence ≤ 0.5.
Datetime: parse; if missing time → keep date, conﬁdence 0.6.
UPI ID regex: ^[\w.\-]{2,256}@[a-zA-Z]{2,64}$.
Never return account numbers in full: mask all but last 4 for display.
9.4 Keyword fallback classiﬁer (classify.py)
Map keywords → type: kyc|pan|aadhaar update → fake_kyc; task|like|youtube|part time|telegram → job_task;
stock|trading|crypto|ipo → investment; cbi|police|customs|arrest|parcel|narcotics → digital_arrest; customer
care|refund|helpline → fake_customer_care; video call|nude|morph → sextortion; loan|app|instant loan →
loan_app. Conﬁdence 0.6 if matched, else other/0.3.
9.5 Fixtures
For every sample image in samples/, store the expected extraction JSON in backend/fixtures/. These are both the cache
and the test oracle.

ﬁller?
It reads evidence with AI, applies RBI eligibility rules, sequences three oﬃcial channels, tracks legal deadlines, and
gives banks a live claims view. Paperwork is only the output.
Why not just the
portal / 1930?
They are the destinations. Most victims never reach all three, in order, on time — and the bank report isn't on the
portal.
Privacy? Victim-shared evidence only, masked ﬁelds, delete on request, no OTP/login. Production runs on the bank's
paid/self-hosted model so data never leaves them.
OCR wrong? User conﬁrms every ﬁeld; manual entry always available.
Is the rule real? RBI Third Amendment Directions 2026, transactions from 1 Jan 2027 (we've read the notiﬁcation).
Why would a bank
pay?
Fewer incomplete claims, faster resolution within 45 days, compliance trail, fraud-trend insight.
Legal risk? We never ﬁle or promise refunds; we prepare and remind. Final eligibility is the bank's decision.
